Notices

One banner, four tones, each pulling its wash, border and foreground from a single status family — so a notice is never assembled by hand. The icon inherits currentColor from the variant's foreground token, which is why none of them carries a colour of its own.

The four tones
success — something landed
afspraak added to your deck · 3 words this visit
info — a neutral fact, not an alarm
You already have this word in your deck
caution — nothing broke, but nothing was found
We couldn’t find “afsprak”
error — something failed and can be retried
The online dictionary didn’t respond. Check your connection and try again.
Which tone, and when

Success confirms an action the user just took, and is the only tone that ever carries a bold word inside it (the word that was added).

Info exists so that "you already have this" doesn't have to borrow caution's yellow. It is a fact about the deck, not a warning — the blue keeps it calm.

Caution is for a dead end that isn't a failure: the lookup ran, and the word genuinely isn't there. It appears with the fuzzy suggestions beneath it, never alone.

Error is reserved for something that actually broke and can be retried — a failed request, a rejected code. It is always paired with a retry control; an error the user can only read is a caution.

Body copy is bold on purpose

Every notice is set in 700 / 16px / 1.55 — heavier than surrounding body text. At these wash opacities a regular weight loses too much contrast against the tinted background, and the banner stops reading as a distinct object. The 24px icon and 12px gap are fixed for all four so a stack of mixed tones keeps one text baseline.
